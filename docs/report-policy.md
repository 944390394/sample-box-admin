# 上报策略 2026.10.22-policy.1

## 入口与生效规则
- 系统设置 → 采样箱 → 默认上报策略：兜底值。
- 采样箱列表：勾选当前页设备或按筛选结果批量设置，预览后冻结目标。单次最多 10000 台；更大范围分批执行。
- 采样箱详情 → 上报策略：单独设置或恢复继承。
- 创建任务单 → 绑定箱子下方：本任务统一策略及逐箱例外。单任务最多 100 台。

优先级：任务内单箱 > 长期单箱 > 任务统一 > 批量 > 系统默认。每层保存完整的周期与定时模式，避免拼接出意外组合。
采样流程：待采样 → 采样中 → 已封箱 → 在途 → 待核验 → 已签收。
调拨流程：待寄出 → 运送中 → 待签收 → 已签收 / 已拒收。
任务开始才取得箱子的策略覆盖权；处理中不能同时执行另一个任务。终结或取消时解除覆盖，恢复当时有效的底层配置。
公司和人员字段记录任务业务信息，本次不自动更改采样箱组织归属；需要转移归属请使用已有分配功能。
任务、关联箱子、策略均保存数据库，刷新和服务重启不会丢失。旧页面内存中的演示任务不作为正式业务数据迁入。

## 权限
角色权限树新增查看上报策略、单箱修改、批量修改、任务与任务策略、系统默认修改五项。系统管理员拥有全部，新操作不自动扩大普通角色权限。设置写权限时同时勾选查看策略及对应页面权限。
所有接口检查目标箱子的数据范围。批量目标中任何一台无权操作时整批拒绝。

## 设备下发与确认
固件 <1.0.2 保留单独 ok，不下发策略，显示固件不支持。
1.0.2+ 接收 `ok p=60 c=0 v=12345678\n`：p 秒，c 是否仅充电，v 策略指纹。
1.0.4 起新增串口回报 `pv=12345678,rp=60,rc=0`。只有版本、实际周期和模式全部匹配才显示已生效；发送成功只显示已发送待确认。
离线设备在下一次上报时下发；仅充电模式未充电时等待事件上报，不能承诺固定时间内收到新策略。所有开关箱、上电和插拔充电器事件保持立即上报。插着充电器时「充电中」和「已充满」来回切换不算事件：服务器把这种充电上报记成「充电状态」（kind=chgs，迁移 038 也改了历史数据），事件列表里不再显示；固件 1.0.13 起这种切换也不再单独上报，随下一条定时上报带上。
更改周期不等于恢复网络；无定时心跳时网页显示等待事件，不能据此判断连接确实在线。
固件 1.0.5 源码及编译文件已准备，网页部署不等于已烧录设备。

## 验收
- 全套后端测试；完整 TypeScript 和 Vite 构建。
- 隔离数据库上的真实 HTTP/TCP 联调：权限拒绝、单箱覆盖批量、任务开始/终结、串口 ACK 与配置回读。
- 新库和旧库升级，设备事件解析、历史开箱次数及存储回读回归。
- 新界面实际浏览器检查使用隔离示例数据，不改真实设备周期。

## 删除档案与恢复出厂
- 网页：采样箱列表/详情可删除「未使用」「停用」的箱子；在途、待激活或关联未结束任务的不能删。删除清档案、上报、策略与下发记录，保留已结束任务单。同一 IMEI 下一包上报按未知设备建档为「待激活」（新箱号），此时出现「激活」。需要 `device:box:delete` 权限，默认仅系统管理员，其他角色须在角色管理中授权。
- 策略状态：固件未知的新档案显示「未生效 · 待首次上报」，不再误报固件不支持。
- 设备（固件 1.0.5）：PB5 内部上拉，连续按住 5 秒恢复出厂，中途松开取消。清除已收下的周期、仅充电限制、策略指纹，开箱次数、离线补传队列和电池曲线，随后软件复位；掉电日志区不擦。按住期间三颗灯只表示恢复进度，松开后立即恢复箱盖/充电/就绪含义。复位后重发 `why=boot`、`pv=0`，周期回到 5 秒。烧录需用 ST-Link，网页部署不会更新设备。

## 删除后抹除与日志导出
- 删除档案时可选「快速抹除 / 完整抹除」（设备固件需 1.0.6+，否则不提供）。服务器按 IMEI 留一条待抹除记录，**档案先保留**，列表和详情显示红色「抹除中」；设备下次上报时在 `ok` 后追加 `wipe m=q|f s=<seq>`，待抹除期间该设备的上报不入库。设备重启后首包 `why=boot` 且 `opens=0` 即视为完成，此时才删除旧档案，并按未知设备重建为「待激活」（新箱号）。记录保留 30 天，到期档案恢复正常；设备固件低于 1.0.6 则不提供抹除。设备一直不上线时，对「抹除中」的箱子再选「不抹除」删除，会撤销请求并立即删档案。
- 导出日志（详情页「导出日志」）：权限 `device:box:logExport`（服务器已存上报，CSV，一次最长 31 天）和 `device:box:dump`（板子本机日志）。后者先让设备回传条数，确认起始日期与上限后再回传，约 7 条一行、1 行/秒，**需要设备在线、网络良好并消耗流量**（DTU 模板每包带 `uart` 和 `uarthex`，每行约 1 KB，1 万条约 1.4 MB），中途断开不续传。两项权限默认仅系统管理员。
- 表：`box_wipe_pending`、`box_dump_request`、`box_dump_record`（迁移 018）。删除档案会清掉该箱的回传数据，待抹除记录保留。

## 指示灯模式

上报策略的每一层（任务内单箱、单箱、任务统一、批量）可以多带一项「STM 指示灯日常亮 / 日常灭」，默认日常亮。

- 下发：确认行在 `c=` 之后、`v=` 之前带 `l=0|1`，例如 `ok p=60 c=0 l=0 v=123`。只对固件 1.0.7 及以上的设备下发，旧固件收到的行和以前完全一样。
- 范围：只管 STM 的开盖、充电、就绪三个灯。长按 PB5 恢复出厂和远程抹除时的进度灯照常点亮。模块（DTU）上的灯是 DTU 分组参数「关闭LED指示」，不在这里设置。
- 版本号：只有明确关灯才参与策略版本哈希，已有策略的版本号不变，升级后不会重新下发。
