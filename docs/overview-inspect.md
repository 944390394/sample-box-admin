## 单位怎么划（录音②③、P4/P5）
- **无采样机构层**：部门类型只有「公司」「检测站」两种（`org-api.js DEPT_TYPES`）。分公司（公司类型）就是采样单位，自采。
- **唯一检测站**：全局恰一个 `type=检测站`、挂总公司子树（org-api 写侧校验唯一＋子树；停用行也占位）。
  配置项 `box.stationDeptId`：采样箱 → 默认策略页「唯一检测站」下拉（原系统设置「采样箱默认策略与任务」分区，IA 迁移；候选＝type=检测站 且启用的部门，读 DeptAPI；
  无候选时灰字引导「先到部门管理把某部门类型改为检测站（须属总公司）」）；保存走 saveBox，要 `device:box:policyDefault`，
  `assertStationSavable` 五类友好报错（不存在/停用/非检测站类型/不属总公司子树/全局唯一冲突），清空不校验。
  未配置时服务端 `resolveStation(db)` 按「总公司下恰一个启用检测站」自动认定；零个/多个→建单友好报错
  「请先在系统设置指定唯一检测站」（A0409，不是 500）——指向的就是上面这个下拉。
  自动认定生效值提示：配置未指定且认定成功时，GET /system/settings（及 saveBox 回读）的 box 载荷带
  `stationAuto={id,name}`（否则 null），下拉旁灰字「自动认定：{name}」；配置已指定时不显示。
- 存量库迁移 056：总公司下恰一个启用 `type=采样机构` 者自动指定为检测站，其余采样机构一律归公司；
  机构节点**改挂不删 id**（P4，生产由管理员在部门页改挂），历史可见性靠 COALESCE(现箱归属,快照) 自动跟随。
- 集团总览列出：所有顶级公司（总公司、各分公司）＋唯一检测站（任意层级，正常数据只有一个）。
- 每个单位的箱子按部门子树算；没分配单位的箱子算在总公司名下。
- 「在仓库」就是箱子状态「未使用」（显示名可在系统设置改）。
- 只能看到一个单位的人点「总览」直接进自己单位的总览。

## 合并采样单（D1/P6：采样＋送检一张单，TK-）
分公司自采，接收方**固定唯一检测站**（服务端强制 `toOrgId=stationDeptId`，总部/分公司不可作接收方，P10）：

主路径 7 步：待采样 → 采样中 → 已封箱 → 在途 → 待签收 → 待检测 → 已检测（终态 OK）

分支：
- **已取消**：待签收之前可取消（待采样/采样中/已封箱/在途）；
- **已拒收**：签收动作可选拒收（终态 VOID）；
- **退回中 → 已退回**：待检测/已检测可发起退回，退回目的地＝**原寄出分公司**（D3），已退回时箱子归属回迁 fromOrg。

寄送方式 trip（单向/双向）整体作废：新建忽略，旧数据只读兼容（`isLegacySample`）。
旧 kind 送检（IN-）/调拨只读保留、不再新建；056 已把存量送检映射进合并口径（待寄出→已封箱、运送中→在途、其余同名；
旧采样 待核验→待检测、已签收/已完成→已检测），保留原 id/IN- 前缀作历史事实。
划拨（AL-）独立保留：提交即生效、归属立即转移，只有 已划拨/已撤销 两态，目标限 `type=公司`（P8，检测站不参与归属划拨）。
划拨/送检功能**常开，无开关**：旧 `box.enableTransferInspect` 开关退役（写入被忽略、读取恒 true），`/sample/transfers*` 恒可用。

## 检测站签收与开箱检测（P2：扫码＋开箱次数差，无视频要求）
1. **扫码签收核验**：检测站扫箱码弹「签收核验」（合并单在「在途」也可直签，系统先自动记一笔「确认到达」）。
   页面列每台箱子的电量、箱盖、本次开箱次数和上限、离收货地址多远。
   - 核验通过：「确认签收」→ 单进**待检测**（不是已签收），也可以拒收。
   - 有异常（开箱超上限、超出到达范围、箱盖开着、设备告警）：只能「拒收」或「强制签收」，都要写原因；
     强制签收在流转记录里记「强制签收」。位置不明只提示，不算异常。
   - 拒收可选退回：退回 → 返程（退回中→已退回），寄出分公司扫码「接收退回」后结束、箱子回到在仓库；
     不退回 → 已拒收直接结束。开箱超限的箱子样品作废，强制签收后也不能开始检测。
2. **签收那一刻，开箱次数定住**：之后检测时开箱不算进本次任务。
3. **开始检测**：每台箱子扫码点「开始检测」（或任务详情箱子列表里点）。这台箱子的本次任务即结束：
   不再占用、回到「未使用」（在仓库），可马上绑新单，开箱次数从新单重新算（「清零」）。
4. 最后一台开始检测后整张单变「已检测」；也可「全部开始检测」一起结束。

板子里的累计开箱次数**不清零**；页面显示的都是「本次任务」开了几次。

## 接口
- `GET /api/v1/sample/tasks/:id/receive?boxId=`：签收核验（箱子状态、开箱、距离、异常、能做的动作）。
- `PUT /api/v1/sample/tasks/:id/status`：合并流推进（采样中/已封箱/在途/待签收/待检测/退回中/已退回/已取消/已拒收）、
  `强制签收`（要原因）。划拨不走通用 transition，走 `POST /sample/transfers/:id/revoke`。
- `POST /api/v1/sample/transfers`：划拨提交即生效（clientToken 幂等）；`GET /sample/transfers/candidate-boxes`。
- `GET /api/v1/sample/overview`：集团总览（units/stationTotal 四数＋今日）。
- `GET /api/v1/sample/overview/:orgId?day=&month=&company=`：单位总览。
- `POST /api/v1/sample/tasks/:id/boxes/:boxId/inspect`：一台箱子开始检测（自动推进整单到已检测）。
- `GET /api/v1/sample/tasks` 默认只列 kind=采样，`allKinds=1` 兜底全部（含历史旧 kind）。
