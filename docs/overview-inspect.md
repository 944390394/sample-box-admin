## 单位怎么划
- **采样机构就是检测站**（2026-11-06 改）：部门类型只有「公司」「采样机构」两种，上一版单独加的「检测站」由迁移 042 并回「采样机构」。
- 集团总览列出：所有顶级部门（总公司、各分公司），加上任何一级的采样机构（按检测站显示）。
- 每个单位的箱子按部门子树算。子树里另有检测站的，那部分箱子算在检测站名下，不重复算。没分配单位的箱子算在总公司名下。
- 「在仓库」就是箱子状态「未使用」。可以在系统设置里把这个状态的显示名改成「在仓库」。
- 只能看到一个单位的人（分公司、检测站的人员）点「总览」，会直接进自己单位的总览。

## 检测站流程
建单时，签收方是「采样机构」类型的单位（调拨的接收单位，或双向采样单寄回的寄出单位），这张单就走检测流程：

调拨：待寄出 → 运送中 → 待签收 →（签收）待检测 →（全部开始检测）已检测

1. **扫码签收核验**：收货方用小程序扫箱码，自动弹出「签收核验」页（箱子还在运送中也可以直接签，系统先自动记一笔「确认到达」）。页面列出每台箱子的电量、箱盖、本次开箱次数和上限、离收货地址多远。
   - 核验通过：「确认签收」，也可以拒收。
   - 有异常（开箱超过上限、离收货地址超出到达范围、箱盖开着、设备告警）：没有「签收」，只能「拒收」或「强制签收」，两者都要写原因。强制签收在流转记录里记成「强制签收」。位置不明（没定位、收货地址没坐标）只提示，不算异常。
   - 拒收时问「是否退回发货点」：退回 → 任务进度加上返程（退回中 → 已退回），寄出方扫码只能「确认接收」，接收后任务结束、箱子回到在仓库；不退回 → 任务直接结束（已拒收），箱子归属不变。
   - 网页任务详情的签收、拒收对话框按同样的规则：列出核验异常，拒收时有「退回寄出单位」勾选（默认勾上）。
2. **签收那一刻，开箱次数定住**：之后检测时开箱，不算进本次任务。
3. **开始检测**：每台箱子在小程序扫码点「开始检测」，或在任务详情的箱子列表里点。点完这台箱子的本次任务就结束：不再占用，回到「未使用」（在仓库），可以马上绑新任务单，开箱次数从新任务开始重新算（就是「清零」）。
4. 最后一台开始检测后，整张单变「已检测」。也可以在任务详情点「全部开始检测」，剩下的一起结束。

板子里的累计开箱次数**不清零**，留着方便追查；页面上显示的都是「本次任务」开了几次。

## 单位总览
- **顶部**：箱子总数、在途、在仓库、待激活、离线、低电量、告警。点一格进采样箱列表，按本单位和这个状态筛好。
- **检测站多三格**：运往本站途中（已寄出、还没签收）、已到未开箱检测、某天已开箱检测，下面列出具体箱子（带本次开箱次数），还有正运往本站的任务单。
- **按日查看任务**：日历每天标出有几张进行中的单，点一天，右边列出那天进行过的任务（那天之前创建、那天还没结束的）。

## 接口
- `GET /api/v1/sample/tasks/:id/receive?boxId=`：签收核验（箱子状态、开箱、距离、异常、能做的动作）。
- `PUT /api/v1/sample/tasks/:id/status`：`强制签收`（要原因）、`已拒收`、`退回中`（拒收并退回，要原因）、`已退回`（寄出方接收）。
- `GET /api/v1/sample/overview`：集团总览。
- `GET /api/v1/sample/overview/:orgId?day=YYYY-MM-DD&month=YYYY-MM`：单位总览。
- `POST /api/v1/sample/tasks/:id/boxes/:boxId/inspect`：一台箱子开始检测。
- 迁移 041 给 `sample_task_box` 加了 `inspected_at`、`inspected_by` 两列；迁移 042 把「检测站」类型并回「采样机构」。
- 工作台的任务待办多了 `inspect`（待检测）一组。
