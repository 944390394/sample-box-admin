# 采样箱 1.0.17 单箱配置与验收

## 安装和回退

1. 导出试验箱现有银尔达分组参数、平台固件版本、三个模板和当前 STM 固件。记录 IMEI、板卡型号、TTL 接线、网络协议、LBS 后台配置及设备原策略。先升级采样箱服务器和管理页面。
2. 将试验箱移到独立分组，确认只使用 TCP 通道 1 和 TTL 串口 1，9600 8N1。新任务接管所有串口和网络接收缓存。其他通道在用时不能采用这个配置。
3. 烧入本项目默认 1.0.17 STM 固件。在平台清空收、发数据模板，将 `firmware/dtu/sampling-task.lua` 的整个 function 至 end 作为唯一任务模板，保存并重启试验箱。平台参数体积限制、内核接口及 FSKV 可用性需核实。模板启动时要求网络、串口接管接口和毫秒时钟。确认上报 lpp=1、fw=1.0.17、rn=1，收到 p/c/t/j/v，回显 pv/rp/rc。新的本地控制命令仅在专用模板识别后使用。
4. 在单箱或任务策略中选“随定时上报定位”或“关闭卫星定位”。新派单使用分配时的单箱有效配置快照，后台在线时尝试推送，离线等下次上行领取。未显式选择时任务默认按次定位，空闲默认关闭。仅充电策略下，电池供电的原有最短 10 分钟心跳约束仍生效。
5. 回退时先撤销试验准入、恢复原分组的三个模板和原 STM 固件，再检查原有策略回包、队列确认和链路心跳。保留同一箱的数据库及外置 Flash 记录。

## 单箱准入

- 空 IMEI 为默认设置。在线低功耗（2026-11-10 起）：在 `ONLINE_IMEI` 填写该台设备后，任务同时调用 `PronetSetNetwt(1000)` 和 `pm.power(pm.WORK_MODE, 2)`。银尔达手册写明网络轮询默认 50 ms 时 `pm.power` 进不了低功耗，两者必须一起设；`PronetSetNetwt` 要 DTU 固件 V2.0.9 以上，固件没有这个接口时两项都不调用，行为和不填一样。BOX-004 当前是 `YED_DTU4_2.0.3`，要先在平台升级 DTU 固件。原来单独试轮询的 `POLL_1000_IMEI` 已去掉。启用后记录整机电流、服务器下发到 STM 的延迟、串口首字节有没有丢、断网重连。
- 深睡仅供验证。STM 默认 `BOARD_DTR_WAKE_LEVEL=-1` 保持 PB0 输入。先确认 DTR 接线、有效电平、允许的驱动电流以及脉宽，在台架验证 1 秒唤醒脉冲后，在试验构建中指定 0 或 1。验证模组能由本地唤醒并按时重新入网后，才在试验模板设置 `DEEP_IMEI`。整机没有通过验收前，使用默认构建。
- 深睡还要求超低功耗 API、FSKV 和已知的看门狗查询接口可用。按提供的银尔达手册，支持硬件看门狗的机型休眠不能超过 200 秒；该软件对这类设备关闭长休眠。上报间隔 ≥600 秒才进入候选，必须同时满足电池供电、无需留在线接单、队列已确认、策略及窗口已保存且读回。STM 和 DTU 用准备与提交消息完成交接；正常周期提前约 60 秒恢复，重新入网和搜星可同时进行。
- 开关箱先持久化，离线期间 STM 记录事件和发生时间；首次对时前无绝对事件时间。开箱刷新两小时窗口，关箱只尝试上报。后台无法用 TCP 联系已退网的 DTU。持续断网时，Flash 容量仍是补传上限。通过调试串口 `queue` 查看落盘/在途记录数、写失败次数 writeerr 和队列满时回收扇区的次数 full；两个故障计数为本次启动累计。STM 掉电且时间未恢复时保守保持在线两小时。
- 每轮最多约 60 秒搜星。STM 将定位采样的经度、纬度和时间随定时记录保存，重传沿用这条记录的坐标。未取得新鲜定位时按时发送。设备状态、对时、指令及开关箱收发均可在搜星期间处理。
- 怎样算新鲜定位（2026-11-10 起）：STM 发出定位请求后，任务记下当时定位库里的最后一条 RMC；之后出现时间更晚的第一条有效定位就采用，坐标的时间取这条 RMC 自己的 UTC 时间。关定位前缓存的旧坐标时间不变，不会被当成新定位。之前要求 RMC 时间和模块网络时间相差不超过 1 秒，模块对时偏一两秒就一直拿不到坐标，已去掉。测试：`firmware/dtu/test-sampling.lua` 覆盖模块时钟快 5 秒、请求后没有新数据两种情况。
- 室内省电（2026-11-10 起）：连续 3 次搜星到时间都没定到位，之后每 3 次定位请求只搜 1 次（仍按 STM 给的时间、最多 60 秒），跳过的那几次不给 GNSS 上电，STM 照常按时上报、不带坐标。定到一次就恢复每次都搜。拿到户外最多 3 个上报周期恢复定位。这段在 DTU 任务里，改了只需在平台重新下发任务，不用烧录 STM。
- 平台任务框能放下的长度没有核实过，已知 10,317 字符可以。项目里的 `sampling-task.lua` 带注释约 1.2 万字符，下发时用去掉注释和缩进的版本（代码相同，约 8,700 字符，同一套测试通过）。

## 实测记录方法

在电池端串接可积分的电流记录仪。记录固件版本、网络信号、天线、LED、供电电压、是否接调试器、周期、每周期电量、定位成功数、下行到 MCU 的时延、队列变化及串口错误。USB 或调试器改变供电/睡眠状态时，分别记录。5 分钟测原配置、在线关闭 GNSS、在线按次定位三组。10 分钟用相同定位配置比较在线与深睡，每组在正常、弱信号下各取至少 10 个完整周期。积分从一个上报点到下一个，包含重连、搜星和发送后回落。

用户提供的厂家数据仅作对照。3.8 V、关闭全部 LED 的在线无数据待机为 6.4–8.2 mA。超低功耗项在 3.8 V、信号 28 测得，连续休眠 46 µA，关闭 GPS 且 3 分钟心跳约 10 mA；每 10 分钟醒来定位并上报约 2.4 mA，每 60 分钟约 0.52 mA，正常网络单次工作约 50 秒。厂家提到发送结束后约 12 秒自动回落。这些项目的工作负载各异，5 分钟的整箱电流需要独立测量。

## 放行条件

- 在睡前、睡中、刚醒、GNSS 搜索中连续开关箱。核对事件时间、次数、顺序、队列号、服务器去重和 9600 双向首帧。
- 在无任务开箱后的第 119 分钟派单，检查后台无需第二次上行即可发出策略，并收到版本回显。重复开箱延长窗口，关箱不延长。窗口结束后派单，定时或开关箱联网时收到当前有效任务；期间取消的任务不会在重连时被重新执行。
- 断网、断电、重启 DTU、丢一次确认，验证未确认事件恢复；无 GPS 的室内环境核对到点上报。关闭卫星定位时测实际供电；验证 DTU 分组的后台 GNSS、LBS 没有自行重新开启定位。
- 好信号、弱信号下深睡每周期耗电均低于在线、差值超过测试波动，并且事件和回显验收通过，才为该硬件组合保留深睡准入。记下原始电流曲线与结果，之后相同板型也应核实固件及唤醒接线。
