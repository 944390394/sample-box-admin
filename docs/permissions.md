# 权限模型：逐项权限点 + 可转授 + 部门权限上限（2026-11-06）

## 三条规则
- **实际权限** =（这个人所有角色的权限之和）∩（从顶级部门到他所在部门，每一级「权限上限」的交集）
- **实际数据范围** = 角色里最宽的那个，但不超过所在部门这条线上最窄的「最大数据范围」
- **能转授的** = 实际权限里、角色上开了「可转授」的那些

系统管理员角色不受部门上限约束（相当于根账号），全部权限、全部数据。

## 参考的做法
| 来源 | 做法 | 借鉴 |
|---|---|---|
| AWS Organizations 服务控制策略（SCP） | 挂在组织单元上沿树继承；账号最终能用的 = 每一层 SCP 的交集 ∩ 自己被授予的；只封顶不授权 | 部门上限沿部门树取交集，只封顶 |
| AWS 权限边界 | 给人设「最多能有」，授予再多也超不过 | 实际 = 角色授予 ∩ 部门上限 |
| 阿里云资源目录管控策略、GCP 组织策略 | 子节点不能放宽父节点 | 下级上限只能在上级范围里勾 |
| 飞书、钉钉分级管理员 | 子管理员的管理范围、功能范围都不能超过授予他的人 | 叠加「可转授」和数据范围 |
| 数据库 `WITH GRANT OPTION`、Keycloak | 能用某项权限 ≠ 能把它交给别人 | 每项权限单独的「可转授」开关 |
| 若依、AWS 控制台的授权页 | 按菜单/模块分组、父子联动、搜索、模板、保存前看变更 | 授权界面 |

## 一项只管一件事
权限名里不写「等」，一项只管一个动作或一类字段。迁移 043、045 把以前合在一起的码拆开，已有角色按原来的码补齐，升级后每个人的实际权限前后一致。

- 每项权限属于一个模块（和菜单对应），分三段：**能进这页 → 能看到什么 → 能做什么**。
- 前置（`needs`）：列出的任意一项有了，这一项才用得上。「能进这页」是这页其他项的前置。
- 字段级遮挡：没有「查看电量」就不给电量相关字段，`masked` 里列出被遮的字段组名（`power`、`lid`、`signal`…）。签收核验、轨迹事件、列表筛选和计数都按同样的字段权限。

## 工作台卡片
每张卡片一项（`monitor:card:*`）：待寄出、待确认到达、待签收、待接收退回、采样待推进、待检测、开箱超限、待激活、告警、在途但离线、低电量、开着盖、最近动态、我保管的箱子、我经手的任务。
卡片要「勾了这张」且「有看里面内容的权限」（目录里的前置，如「低电量」还要「查看电量」）才给数据。迁移 045 按旧卡片组码自动勾上，工作台显示不变。

## 可转授
- 角色上的每项权限多一个「可转授」开关，存在 `sys_role_perm.grantable` 列。
- 非管理员要满足下面两条，才能把某项权限授给别的角色（加上、拿掉、开关可转授都算）：
  - 有「给角色分配权限」；
  - 这项权限在自己的「能转授的」里（角色上开了可转授，且没被自己部门的上限挡住）。
- 给人员分配角色同理：角色里的每项权限，自己都要能转授；数据范围也不能比自己宽。
- 升级时：有「给角色分配权限」或「给人员分配角色」的角色，自己的权限全部可转授；其他角色都不可转授。

## 部门权限上限
- 数据：`sys_dept.perm_limited`（0 跟上级一样 / 1 单独限制）、`sys_dept.max_data_scope`（1–4，空 = 跟上级）、`sys_dept_perm (dept_id, perm)`。迁移 044 建表，现有部门全部「跟上级一样」。
- 计算：`resolveDeptLimit` 从所在部门往上走到顶级，开了限制的层取交集，数据范围取最窄。`resolveAccess` 把 `perms`、`grantable` 都 ∩ 上限，数据范围按上限封顶。
- 保存（要「设置部门权限上限」）：
  - 勾的项必须在上级部门的实际上限里；最大数据范围不比上级宽；
  - 非管理员：部门要在自己管理范围里；收回随便收，放开（这个部门原来用不了、现在能用）要自己能转授；最大数据范围不比自己宽。
- 上级收紧后，下级存着的超出部分不生效，部门页标「上级已收回，不生效」，下一次保存时去掉。
- 分配角色、调部门时只提示不拦：「在这个部门有 N 项不生效」（可以授予，但生效被封顶）。

## 管人范围和看箱范围
- 看箱子（`scope.orgIds`）：箱子挂在单位上，「本单位」「本单位及下级」都把上级单位算进来。
- 管人和部门（`scope.manageOrgIds`）：只有本部门及下级，不含上级，下级管不了上级的人。

## 授权界面（`src/components/biz/PermEditor.vue`，角色页和部门「权限上限」页签共用）
- 左边模块目录显示「已勾 / 总数」，点一下滚过去；窄的时候变成顶部横向标签。
- 每行「拥有」「可转授」两列，列头整列全选；只有这个角色能授权（给角色分配权限、给人员分配角色、设置部门权限上限）时才显示「可转授」列。
- 勾一项自动补上前置并提示；取消前置时列出依赖它的项，确认后一起取消。
- 模块快捷：全部 / 只读（能进这页 + 能看到什么）/ 清空。角色页另有「从其他角色复制」「常用模板」。
- 搜索高亮；筛选 全部 / 已勾 / 可转授 / 我能改的。灰掉的项悬停锁图标看原因（被你所在部门的上限挡住、你自己没有、你有但没开可转授、上级部门没有）。
- 底部保存栏写清新增、收回、可转授变化几项；保存前确认框按模块列出，收回的标红并写明影响几个人。
- 右侧预览：能看到的菜单、工作台卡片、采样箱详情、任务详情。
- 人员页「权限」打开实际权限抽屉：每项写清来自哪些角色，或「角色里有，但被某部门的上限挡住」，以及数据范围怎么算出来的。
