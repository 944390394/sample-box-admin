# 开箱录像：现状与后续方向

## 现在做了什么

- **什么时候录**：采样任务的采样单位是「采样机构」（部门类型）时，创建任务单可以打开「开箱录像」。之后在下面这段时间里，箱子每在计划地点开一次箱，服务器就请求视频平台录一次像：
  - 时间：任务处于「待采样 / 采样中 / 已封箱」。
  - 地点：箱子当前位置在计划地点的误差范围内；计划地点没有坐标时，只要任务在「采样中」就算。
- **请求记录**：每次请求在 `sample_task_video` 里记一条，带任务、箱子、开箱时间、距计划地点的距离和状态。状态有：
  - 待请求
  - 已请求
  - 录制中
  - 已完成
  - 失败
  - 平台未接入
- **请求怎么发**：
  - 平台地址在「系统设置 › 外部集成 › 视频平台」里配。
  - 服务器向这个地址 `POST` 一段 JSON，见下面的「接口约定」；带 `Authorization: Bearer <令牌>`。
  - 请求异步发出，不影响上报处理。
- **没接入时**：没启用或没配地址就不发请求，状态记「平台未接入」。之后配好平台，可以在任务详情里点「重新请求」补发。
- **页面展示**：任务详情的「开箱录像」标签页里，每次开箱一格。
  - 格子上显示箱子、开箱时间、距计划地点多远、请求状态。
  - 有视频地址的点开就能播放。
  - 动态时间线里的开箱事件也带「查看开箱视频」入口：同一台箱子开箱前后 10 分钟内的录像，算这次开箱的。

## 接口约定（以后接平台时按这个对）

服务器发给平台：

```json
{
  "event": "box.opened",
  "requestId": "录像记录编号",
  "taskId": "TK-…",
  "taskName": "…",
  "boxId": "IMEI",
  "boxName": "采样箱_00000001",
  "imei": "…",
  "orgId": "采样机构编号",
  "org": "采样机构名称",
  "openedAt": "2026-10-29 21:23:21",
  "place": { "address": "…", "lng": 114.1, "lat": 22.6 },
  "distanceM": 35
}
```

平台怎么回：

- 返回 2xx 就算受理，状态记「已请求」。
- 返回的 JSON 里带 `url` 时，直接记为「已完成」。

具体平台接入时只改 `server/src/integration/VideoPlatform.js` 这一个文件。

## 后续 UI 方向（这次没做）

1. **平台回调**：录完后平台调回来，把视频地址、封面、时长写进录像记录，状态变成「已完成」。平台按 `requestId` 对应到记录；接口要验签。
2. **时间轴回放**：任务详情里放一条时间轴，开关箱、到达、位置点和视频片段对齐在上面。拖到哪个时间点，地图和视频就跳到哪里。
3. **开箱审核**：核验人员逐段看录像，标「正常 / 异常」并写意见。异常的在任务列表和工作台上标红，进「待我处理」。
4. **缩略图和下载**：格子上显示视频封面和时长；下载时加水印，水印内容是任务编号、箱子名称和开箱时间。
5. **采样机构工作台**：采样机构负责人的工作台上加「今日录像」卡片，显示录像数量、失败条数，点一下可以批量重试。
6. **保留期限**：系统设置里配置录像保留多少天，到期后由平台清理，这边只保留记录。
